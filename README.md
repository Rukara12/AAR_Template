# 리뷰 템플릿

디시인사이드에 **게임 리뷰**를 올릴 때 쓰는 이미지 생성기입니다.
카드를 끌어다 쌓아 한 편을 만들고, 그대로 이미지로 뽑아 갤러리에 올립니다.

브라우저에서만 돌아가고 서버가 없습니다. 이미지는 어디에도 올라가지 않고 내 컴퓨터 안에서만 처리됩니다.

## 왜 이미지로 뽑나

디시 본문은 서식이 거의 남지 않고, 긴 글은 그대로 묻힙니다.
실제로 반응이 좋은 글들은 대부분 스크린샷에 자막을 얹은 이미지를 순서대로 올리는 방식입니다.

## 디시 업로드 규격과 화질

디시 PC 웹·공식 앱은 올린 이미지를 **850×478 로 강제 축소**해 화질을 깎습니다.
그런데 **WebP 로 올리면 그 처리를 통과**해 원본 해상도가 그대로 올라갑니다.
그래서 이 앱은 **WebP · 2배(1700px)** 를 기본값으로 씁니다.

| 항목 | 값 | 이 앱의 대응 |
| --- | --- | --- |
| 강제 리사이즈 | PNG·JPG 는 850px 로 축소됨 | **WebP 출력**으로 우회 (형식 선택 가능) |
| 출력 배율 | — | 1배 850px · **2배 1700px** · 3배 2550px |
| 장당 용량 | 20MB | WebP 2배 합본이 보통 1MB 미만이라 여유가 큽니다 |
| 글당 첨부 | 50장 | 낱장이 50장을 넘으면 합본을 쓰세요 |
| 한 장 최대 높이 | — | WebP 한계(16383px)에 맞춰 16000px 에서 나눔 |
| 파일명 | 한글·영문·숫자만 안전 | 그 외 문자는 자동으로 `_` 로 바꿈 |

넣는 이미지는 최대 2800px 까지 그대로 보관하므로, 배율을 올려도 화질이 살아납니다.

## 쓰는 법

1. 왼쪽 **카드 팔레트**에서 타일을 아래 **문서 구성**으로 끌어다 놓습니다. (클릭하면 맨 아래 추가)
   타일에 커서를 올리면 그 카드가 어떻게 생겼는지 견본이 크게 뜹니다.
2. 목록에서 카드를 끌어 순서를 바꿉니다.
3. **가운데 미리보기에서 바로 고칩니다.** 글은 눌러서, 이미지는 끌어서.
4. 보이는 그대로가 결과물입니다. **내보내기**로 저장해 갤러리에 올립니다.

**문서 구성** 목록에는 **카드 종류만** 적힙니다.
무엇이 어떤 차례로 있는지 보는 곳이라, 내용을 아무리 길게 적어도 줄 모양은 그대로입니다.
그 카드에 뭘 적었는지는 커서를 올리면 보입니다.

### 미리보기에서 바로 고치기

가운데 미리보기가 곧 편집기입니다. 커서를 올리면 고칠 수 있는 자리에 테두리가 뜹니다.

| 대상 | 동작 |
| --- | --- |
| 글 | **누르면** 그 자리에 입력칸이 열립니다. `Esc` 취소, `Ctrl+Enter` 확정 |
| 이미지 | **끌어서** 위치를 옮깁니다 |
| 이미지 | **`Alt`+휠** 로 확대·축소 (그냥 휠은 화면 넘기기) |
| 이미지 | **더블클릭**으로 확대·위치 되돌리기 |
| 이미지 | 오른쪽 위 **✕** 로 그 사진만 지우기 (빈 자리를 누르면 다시 고릅니다) |
| 카드 | 오른쪽 위 **✕** 로 카드째 지우기 |

이미지 넣기, 항목 추가, 정렬·비율 같은 세부 설정은 오른쪽 **카드 속성**에서 합니다.
안 쓸 때는 상단바의 **속성** 버튼으로 접어 둘 수 있습니다.

### 화면이 작게 보일 때

상단바의 **− 100% +** 로 편집기 전체를 최대 200% 까지 키울 수 있습니다.
숫자를 누르면 화면 크기에 맞는 기본값으로 돌아갑니다. 출력 이미지에는 영향이 없습니다.

### 저장할 때

**내보내기**를 누르면 그때 형식·화질을 고릅니다. 평소에는 신경 쓸 필요가 없습니다.

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| 저장 방식 | 세로 합본 한 장 | 순서가 꼬이지 않고 첨부 개수도 아낍니다 |
| 형식 | WebP | 디시의 강제 축소를 통과합니다 |
| 화질 | 2배 (1700px) | 20MB 한도에 여유가 크므로 3배도 됩니다 |

### 스팀에서 바로 가져오기

표지 카드에 **스팀 상점 주소**(또는 앱 번호)를 넣고 **가져오기**를 누르면 이미지를 직접 받아 옵니다.
고른 규격에서 있는 것 중 가장 큰 파일을 씁니다.

| 규격 | 받아 오는 파일 | 크기 |
| --- | --- | --- |
| 헤더 | `header_2x.jpg` → `header.jpg` | 920×430 → 460×215 |
| 메인 캡슐 | `capsule_616x353.jpg` | 616×353 |
| 와이드 히어로 | `library_hero_2x.jpg` → `library_hero.jpg` | **3840×1240** → 1920×620 |
| 세로 캡슐 | `hero_capsule_2x.jpg` → `hero_capsule.jpg` | 374×448 |
| 라이브러리 | `library_600x900_2x.jpg` → … | 600×900 → 300×450 |

`header_2x.jpg` 는 최신 게임에만 있습니다. 없으면 460×215 로 내려가니,
2배·3배로 크게 뽑을 거면 **와이드 히어로**가 가장 또렷합니다.

스팀 상점 API(JSON)는 CORS 를 막아 두지만 이미지 CDN 은 열어 둡니다.
캔버스도 오염되지 않아서 그대로 그려 내보낼 수 있습니다.

### 상점 주소 한 번으로

**표지 카드**와 **게임 정보 카드**가 같은 주소 칸을 씁니다.
어느 쪽에서 **가져오기**를 눌러도 둘 다 채워집니다. 넣은 주소는 문서에 남아 다른 카드에도 그대로 보입니다.

| 카드 | 채우는 것 |
| --- | --- |
| 표지 | 헤더 이미지, 제목이 비어 있으면 게임 이름 |
| 게임 정보 | 개발자 · 출시일 · 장르 · 가격 · 평가 |

이미 적어 둔 **글자 값은 덮어씁니다.** 받아 온 값이 맞기 때문입니다.
**직접 올린 표지 사진은 덮지 않습니다.** 날아가면 되돌리기 힘드니까요.
(단, 그 표지 카드에서 직접 누르면 새로 받습니다)

| 받는 곳 | 채우는 항목 | 설정 |
| --- | --- | --- |
| `api.steamcmd.net` | 개발자 · 배급사 · 출시일 · 장르 · 전체 평가 · 메타크리틱 · 한국어 지원 | 없음. 항상 됩니다 |
| 상점 API + 프록시 | 가격(원화·할인율) · 최근 평가 · 한국어 평가 | 기본으로 켜져 있습니다 |

플레이 시간처럼 스팀에 없는 값이 필요하면 **항목 추가**로 직접 만들어 적으면 됩니다.
([HowLongToBeat](https://howlongtobeat.com) 같은 곳을 보세요)

**왜 둘로 나뉘나.** 상점 API(`store.steampowered.com`)는 CORS 를 막아 두어 브라우저에서 못 부릅니다.
`api.steamcmd.net` 은 CORS 를 열어 두어서 그냥 불러집니다. 다만 가격·언어별 평가는 지역마다 달라서
상점 쪽에만 있고, 그건 프록시를 한 겹 거쳐야 합니다. SteamDB 는 CORS 도 없고 봇 차단까지 걸려 있어
어느 쪽으로도 안 됩니다.

프록시는 `api.allorigins.win` 을 먼저 쓰고 안 되면 `r.jina.ai` 로 넘어갑니다. 둘 다 남의 공짜 서버라
느리거나 멈출 수 있습니다. 그때는 1단계 항목만 채우고 알려 줍니다.
직접 띄우려면 `js/io/steamapi.js` 의 `PROXIES` 만 고치면 됩니다.

- 셋을 한꺼번에 부릅니다. 차례로 부르면 나이 확인이 걸린 게임에서 30초를 넘겼습니다
- 나이 확인이 걸린 게임은 페이지 대신 API 로 넘어갑니다. 최근 평가만 못 받습니다
- 최근 평가를 못 받았으면 전체 평가로 대신합니다
- 프록시 체크를 끄면 1단계 항목만 채웁니다. 대신 빠릅니다

받아 오기는 `js/io/steamapi.js`, 카드에 얹는 것은 `js/io/steamlink.js`,
상점 페이지 글을 읽는 규칙은 `js/io/steamtext.js` 에 모여 있습니다.
검사는 `outputs/` 의 `steamapi_test.mjs` · `steamlink_test.mjs` · `steamtext_test.mjs` 로 돌립니다.

### 이미지 여러 장 한꺼번에

창에 이미지 파일 여러 개를 떨어뜨리면 **그 수만큼 자막 스샷 카드가 생깁니다.**
스샷 20장짜리 리뷰도 한 번에 깔아 놓고 자막만 채우면 됩니다.
(**문서 ▾ → 스샷 여러 장 넣기** 로도 같은 일을 합니다)

### 단축키

| 키 | 동작 |
| --- | --- |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 되돌리기 / 다시하기 |
| `Ctrl+클릭` | 카드 여러 장 골라 잡기 |
| `Shift+클릭` | 여기까지 한 번에 고르기 |
| `Alt+↑` `Alt+↓` | 고른 카드를 한 칸 위·아래로 |
| `Delete` | 고른 카드 지우기 |
| `Ctrl+V` | 고른 카드에 이미지 붙여넣기 |
| `Ctrl+S` | 프로젝트 파일로 저장 |
| `?` | 조작법 보기 |

되돌리기는 글자를 잇달아 칠 때는 한 덩어리로 묶이므로, 한 번 누르면 방금 친 문장이 통째로 돌아갑니다.

### 저장 자리

작업 내용은 브라우저에 자동 저장됩니다.
리뷰를 여러 편 쓴다면 **문서 ▾ → 보관함** 에 이름을 붙여 담아 두세요.
다만 브라우저 안에만 있으므로, 오래 남길 것은 **프로젝트 저장**으로 `.json` 파일에 따로 보관하는 편이 안전합니다.

내보낸 파일 이름은 날짜로 붙습니다 (`리뷰_260920.webp`).

## 카드 종류

> **카드 팔레트와 «빈 카드» 로 시작하기는 아직 실험적입니다.**
> 손이 많이 간 쪽은 **리뷰 카드** 기본 구성(표지 · 게임 정보 · 평점 · 장단점 · 총평)입니다.
> 카드를 더 넣거나 빼는 것은 됩니다만, 아직 다듬는 중입니다.

팔레트는 **리뷰에서 놓이는 순서**대로 묶여 있습니다. 위에서 아래로 훑으면 한 편이 완성됩니다.
묶음마다 색이 달라서 목록에서도 어느 단계 카드인지 바로 보입니다.

| 묶음 | 카드 | 쓰임 |
| --- | --- | --- |
| **시작** | 표지 | 스팀 헤더 이미지. 상점 주소만 넣으면 바로 받아 옵니다 |
| | 게임 정보 | 개발자 · 장르 · 출시일 · 가격 · 최근 평가 · 한국어 평가 (상점 주소만 넣으면 자동) |
| **본문** | 자막 스샷 | 스크린샷 + 자막. 가장 많이 쓰는 형태 |
| | 나레이션 | 본문 글 |
| | 섹션 제목 | `2. 전투` 같은 큰 구분 |
| | 스샷 묶음 | 여러 장을 2~3열 격자로 (최대 6장) |
| | 좌우 비교 | 전 / 후 두 장 |
| **평가** | 평점 | 항목별 막대 + 총점 (비우면 평균 자동) |
| | 장단점 | 좋은 점 / 아쉬운 점 두 열 |
| | 총평 | 한 줄 평 + 추천 대상. 마무리 |
| **곁들이기** | 인용 강조 | 큰 한 줄 |
| | 장면 전환 | — 10시간 뒤 — |
| **캐릭터** | 캐릭터 대사 | 이미지 + 대사 |
| | 캐릭터 소개 | 등장인물 한 장 |

묶음 제목을 누르면 접힙니다. 접은 상태는 기억합니다.
**캐릭터** 는 처음부터 접혀 있습니다 — 자주 쓰지 않는 묶음은 `js/cards/registry.js` 의
`DEFAULT_COLLAPSED` 에 이름만 넣으면 됩니다.

### 카드끼리 맞춰 둔 것

| 무엇 | 어디서 정하나 |
| --- | --- |
| 카드 바깥 테두리 | `js/canvas/render.js` 가 모든 카드에 한 번씩 그립니다 |
| 사진 여백 24px | `js/canvas/layout.js` 의 `FRAME` · 쓸 수 있는 폭은 `FW` |
| 사진 둘레 선 | `imageEdge()` 하나로 통일 |
| 글 여백 46px | `PAD` · 본문 폭은 `CW` |

사진을 넣는 카드는 `FRAME`·`FW` 를, 글만 있는 카드는 `PAD`·`CW` 를 씁니다.
숫자를 직접 적지 않으면 새 카드를 만들어도 여백이 저절로 맞습니다.

## 톤 바꾸기

상단바 **문서 ▾ → 톤** 에서 고릅니다.
기본은 **기본 (검정)** — 강조색 없이 흰색만 쓰는 무채색이라 어떤 게임 스크린샷 옆에 놓아도 튀지 않습니다.
그 외에 **따뜻한**, **중세·양피지** 가 있고, 새 톤은 `js/theme.js` 에 항목 하나만 추가하면
고르는 목록에 자동으로 들어갑니다.

## GitHub Pages 배포

저장소 **Settings → Pages → Build and deployment**에서
Source 를 `Deploy from a branch`, Branch 를 `main` / `/ (root)` 로 두면 그대로 올라갑니다.
빌드 과정이 없는 정적 파일이라 별도 워크플로가 필요 없습니다.

## 로컬에서 열 때

ES 모듈을 쓰기 때문에 `index.html` 을 파일로 바로 열면 브라우저가 막습니다.
간단한 서버를 띄워서 열어 주세요.

```bash
python -m http.server 8080
# http://localhost:8080
```

파일을 고쳐도 화면이 그대로면 브라우저 캐시입니다. `Ctrl+Shift+R` 로 새로 고치세요.

```
  io/

    store.js          IndexedDB 보관소
    project.js        자동 저장 · 보관함 · 프로젝트 파일
    export.js         WebP·PNG 내보내기
```

## 되돌리기가 되는 이유

카드를 고칠 때 그 자리에서 값을 바꾸지 않고 **새 객체로 갈아 끼웁니다.**
그래서 이력에 담아 둔 옛 상태가 나중에 덮어써지지 않고, 손대지 않은 카드는 객체를 그대로 공유하므로
이력 100단계를 쌓아도 메모리를 거의 안 먹습니다. (스크린샷이 dataURL 이라 통째로 복사하면 금방 수백 MB 가 됩니다)

카드를 새로 만들 때도 이 규칙만 지키면 됩니다 — 값은 항상 `patch()` 로 바꾸고, `card.foo = x` 처럼 직접 쓰지 않기.

## 카드 새로 만들기

`js/cards/내카드.js` 를 만들고 `registry.js` 에 두 줄만 더하면 끝입니다.
팔레트 · 편집 폼 · 미리보기 · 내보내기는 자동으로 따라옵니다.

```js
import { T } from '../theme.js';
import { W, PAD, CW, text, textZone } from '../canvas/layout.js';

export default {
  id: 'mycard',
  name: '내 카드',
  desc: '설명 한 줄',
  group: '연출',
  accent: '#c8973f',

  create: () => ({ body: '' }),

  // 편집 폼은 이 스키마로 자동 생성됩니다.
  // 쓸 수 있는 타입: text textarea number range select toggle image strlist pairs note
  fields: [
    { k: 'body', t: 'textarea', label: '내용', rows: 4 }
  ],

  label: c => c.body || '내 카드',

  // 높이를 먼저 재고, 나중에 그립니다.
  build(c) {
    const body = text(c.body, { size: 20, maxW: CW, lh: 36 });
    const h = 30 + body.h + 30;
    return {
      h,
      // zones 를 넣어 주면 미리보기에서 바로 고칠 수 있게 됩니다.
      // 글은 textZone(키, 잰 결과, x, y), 이미지는 imageZone(키, 조절값키, x, y, w, h)
      zones: [textZone('body', body, PAD, 30, { multiline: true })],
      paint(ctx) {
        ctx.fillStyle = T.bg;
        ctx.fillRect(0, 0, W, h);
        body.paint(ctx, PAD, 30);
      }
    };
  }
};
```

`paint` 안에서 위치를 계산하지 말고 `build` 위쪽에서 정해 두세요.
그래야 그리는 자리와 고치는 자리가 어긋나지 않습니다.
